# Business Requirements

## 1. Создание цели

### Бизнес-требование
1. Создать цель может либо ментор для своих менти, либо пользователь сам для себя
2. У каждого исполнителя цели не должно быть больше двух активных целей на момент создания новой, иначе создать новую цель нельзя

### Анализ
При создании цели возможны два сценария:
- пользователь создаёт цель для себя;
- ментор создаёт цель для своих менти.

Сценарий определяется наличием `mentorId` в DTO.

Если `mentorId` отсутствует, текущий пользователь становится участником цели.

Если `mentorId` передан, необходимо проверить, что текущий пользователь является этим ментором, а указанные пользователи являются его менти.

Перед созданием цели необходимо проверить количество активных целей каждого участника.

Если у участника уже две активные цели, создание новой цели невозможно.

После успешного прохождения проверок создаётся и сохраняется новая цель.

### Алгоритм
1. Получить `userId` из `UserContext`.
2. Найти пользователя в БД.
3. Если пользователь не найден — ошибка.
4. Получить `mentorId` из DTO.
5. Если `mentorId` отсутствует — создать цель для текущего пользователя.
6. Если `mentorId` передан — проверить, что он соответствует текущему пользователю.
7. Получить менти текущего пользователя.
8. Проверить, что указанные участники являются его менти.
9. Проверить количество активных целей каждого участника.
10. Если у участника две или более активных цели — ошибка.
11. Создать `Goal`.
12. Установить ментора и участников.
13. Сохранить `Goal`.
14. Вернуть `GoalDto`.

### Реализация
GoalService.createGoal()

## 2. Принятие приглашения в цель

### Бизнес-требование
1. Пользователь может принять приглашение, если у него меньше 3 активных целей одновременно, а также если он еще не присоединился к этой цели раньше.
2. Принять или отклонить приглашение может только тот пользователь, кому оно было адресовано
3. При принятии приглашения пользователь добавляется в участники соответствующей цели, а приглашение переводится в соответствующий статус.

### Анализ
При принятии приглашения необходимо выполнить несколько проверок.

Сначала необходимо проверить количество активных целей пользователя.
Для этого из базы данных необходимо получить цели пользователя и проверить, что количество активных целей меньше 3.

В репозитории существует метод:

`Stream<Goal> findGoalsByUserId(long userId)`

Также необходимо проверить, что пользователь ещё не является участником цели, к которой относится приглашение.
Для этого из цели необходимо получить список её участников и проверить, есть ли в нём пользователь, принимающий приглашение.

Кроме того, принять приглашение может только тот пользователь, которому оно было адресовано.
Для этого необходимо получить `invitedId` из приглашения и сравнить его с `userId`, полученным из `UserContext`.

После успешного прохождения всех проверок необходимо добавить пользователя в список участников цели, изменить статус приглашения и сохранить обновлённые данные.

### Алгоритм
1. Получить `userId` текущего пользователя из `UserContext`.

2. Получить из приглашения `invitedId`.

3. Сравнить `invitedId` с `userId` текущего пользователя.

4. Если `invitedId` не совпадает с `userId` текущего пользователя — выбросить ошибку.

5. Получить все активные цели пользователя.

6. Проверить количество активных целей.

7. Если количество активных целей больше или равно 3 — выбросить ошибку.

8. Получить из приглашения `goalId`.

9. По `goalId` найти соответствующую цель.

10. Получить список участников этой цели.

11. Проверить, что текущий пользователь ещё не является участником цели.

12. Если пользователь уже является участником цели — выбросить ошибку.

13. Добавить пользователя в список участников цели.

14. Изменить статус приглашения.

15. Сохранить обновлённое приглашение.

16. Сохранить обновлённую цель.

### Реализация
GoalInvitationService.acceptInvitation()

## 3. Регистрация на мероприятие

### Бизнес-требование
1. Пользователь не может зарегистрироваться на мероприятие повторно.
2. Пользователь может зарегистрироваться на мероприятие только при наличии свободных мест.

### Анализ
При регистрации пользователя на мероприятие необходимо проверить, что пользователь ещё не зарегистрирован на это мероприятие.

Также необходимо проверить количество уже зарегистрированных участников и количество доступных мест на мероприятии. Если свободных мест нет, пользователь не может зарегистрироваться.

После успешного прохождения проверок пользователь добавляется в список участников мероприятия.

### Алгоритм
1. Получить `userId` текущего пользователя.

2. Проверить, что такой пользователь существует.

3. Получить `eventId` мероприятия.

4. По `eventId` найти соответствующее мероприятие.

5. Получить список участников мероприятия.

6. Проверить, есть ли текущий пользователь среди участников.

7. Если пользователь уже зарегистрирован — выбросить ошибку.

8. Проверить количество участников и доступное количество мест.

9. Если свободных мест нет — выбросить ошибку.

10. Добавить пользователя в список участников мероприятия.

11. Сохранить обновлённое мероприятие.

### Реализация
EventParticipationService.registrationParticipant()

## 4. Получение предложенного навыка

### Бизнес-требование
1. Пользователь может присвоить себе скилл, если этот скилл ему рекомендовали не менее трёх разных пользователей.
2. Пользователь не может присвоить себе скилл, который у него уже есть.
3. Присвоить скилл может только тот пользователь, которому этот скилл был рекомендован.

### Анализ
Пользователь может получить предложенный скилл, если выполняются все необходимые условия.

Сначала необходимо проверить, что текущий пользователь является пользователем, которому был предложен этот скилл.

Затем необходимо проверить, что такой скилл существует и что у пользователя ещё нет этого скилла.

После этого необходимо получить пользователей, которые рекомендовали данный скилл, и проверить количество уникальных пользователей.

Если скилл рекомендовали не менее трёх разных пользователей, пользователь может присвоить его себе.

### Алгоритм
1. Получить `userId` текущего пользователя из `UserContext`.

2. Проверить, что пользователь существует.

3. Проверить, что текущий пользователь является пользователем, которому был предложен скилл.

4. Если пользователь не является получателем скилла — выбросить ошибку.

5. Найти скилл в базе данных.

6. Проверить, есть ли этот скилл у пользователя.

7. Если скилл уже есть у пользователя — выбросить ошибку.

8. Получить пользователей, которые рекомендовали данный скилл.

9. Проверить количество уникальных пользователей, которые рекомендовали скилл.

10. Если скилл рекомендовали менее трёх разных пользователей — выбросить ошибку.

11. Добавить скилл пользователю.

12. Сохранить обновлённого пользователя.


### Реализация
SkillService.acquireSkillFromOffers()

## 5. Создание рекомендации

### Бизнес-требование
1. Один пользователь может оставить другому пользователю рекомендацию не чаще одного раза в 6 месяцев.
2. Пользователь не может оставить рекомендацию самому себе.
### Анализ
При создании рекомендации необходимо выполнить две основные проверки.

Сначала необходимо проверить, что автор и получатель рекомендации являются разными пользователями.

Затем необходимо проверить, существует ли уже рекомендация от этого автора этому получателю.

Если рекомендации ещё нет, её можно создать.

Если рекомендация уже существует, необходимо проверить дату её создания. Если с момента создания прошло менее 6 месяцев, создать новую рекомендацию нельзя. Если прошло 6 месяцев или больше, новая рекомендация может быть создана.

### Алгоритм
1. Получить `authorId` и `receiverId`.

2. Найти автора рекомендации по `authorId`.

3. Найти получателя рекомендации по `receiverId`.

4. Проверить, что автор и получатель являются разными пользователями.

5. Если `authorId` и `receiverId` совпадают — выбросить ошибку.

6. Найти существующую рекомендацию от данного автора данному получателю.

7. Если рекомендации не существует — создать новую рекомендацию.

8. Если рекомендация существует — проверить, прошло ли с момента её создания 6 месяцев.

9. Если прошло меньше 6 месяцев — выбросить ошибку.

10. Если прошло 6 месяцев или больше — создать новую рекомендацию.

11. Сохранить рекомендацию.

### Реализация
RecommendationService.createRecommendation()
